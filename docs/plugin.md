# 插件版：在原版 Sub2API 中使用 STATE Kit

插件版使用官方 **Sub2API v0.2.7** 的 `.s2plugin` 接口。基础功能无需修改宿主；**分组 / 账号下拉、账号名称、IP 管理代理选择、手动查找及代理 / 模型测试**需要额外安装[v0.3.4 宿主适配](plugin-host-directory.md)。它与本仓库基于 v0.2.6 的增量版、完整部署版是三个可选入口，**选择一种即可**。

- 下载：[插件版 v0.3.4](https://github.com/wangyunjeff/sub2api-state-kit/releases/tag/v0.3.4)
- 安装文件：`sub2api-state-kit_plugin_v0.3.4.s2plugin`
- 完整插件源码：`sub2api-state-kit_plugin_v0.3.4_source.zip`，或本仓库的 [`plugin/`](../plugin/)
- 包含 Linux amd64、Linux arm64、macOS arm64 三个运行时；宿主自动选择对应架构。
- 官方接口基线：[v0.2.7 / aea725f](https://github.com/Wei-Shaw/sub2api/tree/aea725f2ea644d5592d0bbb1d63b607efa7e200a)。清单兼容范围为 `>=0.2.7 <0.3.0`，实际验证基线为 0.2.7，其他版本仍需测试。

## v0.3.4：按分组选择账号

### 可选的强制 Astra

插件配置页提供“强制使用 Astra”开关。开启后，已启用的账号请求会在发往上游前将 JSON 请求体中的顶层 `model` 改为 `gpt-6-astra`；票据采集、复验、缓存和响应模型观察也统一按该模型执行。关闭开关后恢复客户端原始模型。该功能默认关闭，不修改客户端展示的模型名称，也不影响未加入插件账号列表的请求。

在「选择需要票据的账号」中选择分组，再选择账号并点「添加」；账号显示名称和 ID。支持「全部分组」「未分组」，已添加的账号自动排除。分组只用于筛选，不修改账号在 Sub2API 中的分组或代理。

插件停止时也可加载目录；新增账号默认关闭，先保存设置再开启。仅切换下拉选择不会保存配置、采集票据或发送模型请求，刷新不会覆盖未保存草稿。

**分组下拉需要更新到本版宿主适配并重建宿主前端。** 旧宿主仍可输入账号 ID；安装包不会自行修改宿主。

**如果「测试并应用代理」「查找票据」都是灰色，且显示「插件未运行」：** 关闭配置窗口，在插件管理的 STATE Kit 卡片点击「启用」，再打开配置。页面里的「使用 STATE」和账号开关控制票据使用，不能代替宿主启动插件进程。

## 手动操作

在插件配置页：

- 修改某行账号开关后立即保存，只保存该账号开关，不覆盖其他表单草稿。新增账号仍先保存完整配置。
- 「查找票据」对该账号跳过冷却、立即启动新一轮采集；已在获取时合并重复点击。仍有效的旧票据会保留，新票据通过复验后替换。需要总开关和账号开关已保存开启。
- **无可用票据也放行默认开启**：有可用票据则注入，没有票据、正在获取或获取失败时按原业务代理转发。上游自身的错误仍原样返回。关闭此开关才恢复原有无票据 503 行为。旧配置未设置此字段时按开启处理。
- 「手动测试 / HTML 预览」选择账号、模型、提示词，点「测试模型」。测试遵循当前账号及总开关；取消勾选 STATE 选项可做无票据对照。它是管理员直测，走账号业务出口，不经过 API Key 用量计费。
- 「检测出口 IP」可选择账号业务出口、动态代理（含前置代理）、服务器直连；可填预期 IP 对比。独立 IP 查询不等于下一条模型连接一定使用相同 IP。
- 输出用纯文本显示，点击预览才在沙箱 iframe 中运行内联 HTML/动画，隔离管理后台并限制外部网络。需要外部 CDN 的页面可能不能完整呈现。

模型测试最多 3 分钟，提示词最多 24000 字节、回答最多 256 KiB；一次只运行一个手动测试，可点停止。结果仅保留最近一次，在插件进程内保存，不写入配置、票据 KV 或日志；重启后清空。返回模型一致只是可观测指标，不代表智商评分。

上述动作及预览需要 v0.3.3 对应的[宿主适配](plugin-host-directory.md)。已有 v0.3.2 目录适配也需更新并重建宿主前后端。

## 功能和入口

进入 **插件管理 → STATE Kit · 账号级票据 → 配置**，在一个页面里填写动态代理池，选择分组与账号后分别开启 STATE、选择 Pro（292）或 Team（332）和目标模型。

| 功能 | 插件版行为 |
| --- | --- |
| 全局动态池 | 填一次，用于启用账号的后台采集；支持 HTTP(S)、SOCKS5(h) 和会话占位符 |
| 前置代理 | 直连、手动 URL、选择 IP 管理中的代理三种方式；第三种需宿主资源目录适配 |
| 出口与运行日志 | 可选检测公网出口；展示采集、复验、续期和守护的最近 200 条记录 |
| 账号开关 | 默认全部关闭；只为明确开启的账号和模型采集、注入和守护 |
| Pro / Team | 手动选择，分别筛选 292 / 332 字节的 STATE |
| 固定出口复验 | 采集响应模型匹配后，再用该账号原有业务代理携带候选 STATE 复验 |
| 后台续期 | 默认有效期 60 分钟、提前 10 分钟续期；失败保留仍有效的旧票据 |
| 动态守护 | 观察响应中的 312 字节 STATE 或完整成功响应的模型不符，作废本次所用票据并重采 |
| 重启恢复 | 通过宿主的 Redis KV 保存已验证票据和到期时间；不延长原到期时间 |
| 正常账号 | 不采集、不注入、不守护，按宿主给出的业务代理转发 |

官方 0.2.7 仅提供账号 ID；安装资源目录适配后，添加账号处、账号行、状态和日志会显示「名称 · ID」。未适配宿主仍显示 ID，并明确提示。**配置入口不在原有“编辑账号”弹窗中**；向那个弹窗加控件需要修改宿主源码，增量版和完整版仍提供该入口。

## 第一次安装

### 1. 配置信任公钥

官方只内置信任它自己的插件发布者。第三方插件必须在宿主 `config.yaml` 中追加发布者公钥，**只需配置一次**。下载 Release 中的 `trusted-publisher.yaml`，把其中 `plugins.trusted_publishers.state-kit-release-v1` 合并到原配置中；不要用整个示例覆盖自己的数据库、Redis 或其他设置。

公钥也在仓库的 [`publisher-public-key.txt`](../plugin/release/publisher-public-key.txt) 中。公钥可以公开，它不是 API Key 或代理密码。不要开启 `allow_unsigned`。

使用官方 Docker 数据目录时，配置通常在容器 `/app/data/config.yaml`（以实际 `DATA_DIR` 和挂载为准）；裸机安装使用该实例现有的配置文件。保存后重启 **Sub2API 应用服务**使公钥生效，数据库和 Redis 无需重建。生产实例应安排可接受的重启窗口。

### 2. 上传并启用插件

1. 在 Sub2API 的插件管理中上传 `.s2plugin`。
2. 确认名称为 `STATE Kit · 账号级票据`、发布者签名受信任、宿主兼容。
3. 如果已经启用官方 OpenAI OAuth Transport，先停用它。**官方宿主只允许同时启用一个同类传输插件**，二者不能叠加运行。
4. 启用 STATE Kit，灰度比例设为 **100%**。是否使用 STATE 再由插件内的账号开关控制。

### 3. 配置需要处理的账号

1. 先在原账号管理里设置账号的固定业务代理。
2. 打开插件配置，选择「前置代理」方式：
   - **直连动态代理**：当前服务器可以直接连接动态池时使用。
   - **手动填写前置代理**：填写完整 HTTP(S) / SOCKS5(H) URL，例如 `http://127.0.0.1:7890`。
   - **选择 IP 管理中的代理**：需[宿主资源目录适配](plugin-host-directory.md)，下拉选择已有代理。插件只保存代理 ID，每次采集前读取最新地址和认证；删除、禁用、过期或解析失败会明确报错，不会静默改成直连。

   采集走 **当前机器 → 前置代理 → 动态代理 → 上游**。国内部署可勾选「固定业务代理也经过此前置代理」；此时普通请求、模型测试与票据复验走同一前置代理，再连接账号固定业务代理，最终出口仍由固定代理决定。Docker 中的 `127.0.0.1` 指向容器自身，须填写容器可达地址。已有 v0.3.1 配置自动识别为直连或手动方式。

3. 继续填写全局动态池，例如：

   ```text
   socks5h://ENCODED_USERNAME-sid-{sid}:ENCODED_PASSWORD@PROXY_HOST:PORT
   ```

   用户名和密码中的特殊字符须分别进行 URL 百分号编码。`{sid}` / `{random}` 用于轮换会话；服务商是否更换实际出口，以其行为为准。不要填“获取代理列表”的 HTTP API 地址。

4. 选择分组和账号并添加（旧宿主可输入 ID），选择 Pro / Team，填写要保护的目标模型，打开账号开关。
5. 按需勾选「检测出口 IP 并写入运行日志」。它会在每次采集、业务出口复验和恢复复验时，通过该次代理会话请求 `https://api.ipify.org?format=json`，只发送 IP 查询，不发送账号授权、STATE 或模型内容。每次查询最多 10 秒，失败后继续模型探测。
6. 按需开启「自动续期与补票」，打开插件内 STATE 总开关并点击「保存设置」。关闭自动续期时，点击账号行「查找票据」手动获取；只有票据状态可用时才会实际注入 STATE。

不要同时让宿主内置 STATE 功能或其他扩展向同一账号注入票据。插件不会自动搬运旧版的账号配置或已有 STATE。

“测试已保存配置”只检查插件与宿主服务配置状态；它不等于模型恢复成功。是否有可用票据，以票据状态和实际响应模型为准。

## 查看运行日志

配置页底部每 5 秒只读刷新，最多显示当前插件进程的最近 200 条记录。页面日志包含账号名称（宿主支持时）、ID、阶段、尝试次数、检测到的出口 IP、HTTP 状态、实际返回模型、STATE 长度和耗时。密码、完整代理 URL、OAuth Token、STATE 原文和请求内容不会写入这些日志。同样的结构化记录写入插件 stderr，是否保存和轮转由宿主运行环境决定。

- 「动态采集 · 前置代理」：通过两层代理采集候选票据。
- 「业务出口复验」：使用该账号原来的业务代理（或无代理直连）验证候选票据。
- 「票据可用」：只有候选票据满足筛选条件并通过业务出口复验后才出现。
- 「返回模型不匹配」：展示完整响应中的实际模型，继续下一次有界尝试。

**检测出口 IP 是同一代理会话上的独立 IP 查询结果。** 代理商可能按新连接或目的地址轮换出口，所以它不能证明下一条模型请求的精确源 IP。插件没有把代理服务器地址冒充公网出口，手动查找时，业务出口检测失败会停止，单次动态出口失败按设定次数换会话重试；自动采集中的可选 IP 观察失败会记录并继续模型探测。刷新日志不会触发新探测。

## 关闭、升级和回退

- **只关闭某个账号的 STATE：** 在插件配置里关闭该账号，开关立即保存。
- **暂停全部采票/注入：** 关闭插件配置里的 STATE 总开关并保存。
- **恢复宿主原生传输：** 在插件管理里停用 STATE Kit；如需使用官方传输插件，再启用原插件。
- **升级：** 下载新版本签名包，在测试实例验证后按宿主插件管理流程更新。保留自己的配置和数据备份。

插件停用后，宿主仍照常负责账号、计费和 API 服务；已经开始的请求由宿主的停用排空机制处理。

## 与增量版 / 完整版的区别和边界

- 本版配置集中于**插件页面**，保留按账号控制的逻辑，但不改宿主账号表单和调度器。
- 宿主 100% 灰度时，所有 OpenAI OAuth 账号经过插件传输，即便它们的 STATE 开关关闭。命中插件的 OAuth WebSocket 由宿主切为 HTTP Bridge；不能理解为未选账号的底层路径完全不变。API Key 账号和其他平台不进入本插件。
- 旧版及关闭「无可用票据也放行」时，已启用的账号/目标模型无有效票据会返回暂不可用响应；v0.3.3 默认放行无票据请求；它无法像源码版一样提前将该账号从宿主调度器移出。请先等采集成功再测试，宿主如何调度其他账号仍由原配置决定。
- **本版支持单个 Sub2API 应用实例。** 官方 KV 接口没有原子分布式锁，多副本可能重复采集、相互覆盖状态，不宣称支持多副本协调。宿主保存配置时可能短暂启动验证进程；插件延迟 5 秒启动采集来减少重复探测，但该延迟不等于分布式锁。
- 票据按同账号、同模型、套餐、配置和固定代理进行绑定；不跨账号转移，不保存 OAuth Token，不修改模型字段或重放已完成请求。
- 宿主加密保存插件配置。票据通过有 TTL 的宿主 Redis KV 保存；该 KV 本身不是额外的票据加密库，应沿用现有 Redis 的访问控制。
- 292 / 332 / 312 是本地实验使用的长度条件，并非模型身份或质量证明。必须同时核对完整成功响应的模型；本地有效期也不是上游承诺。
- 401 / 403 / 429 停止当轮采集并进入冷却；不开无限重试，不承诺消除配额限制或一定能拿到可用 STATE。
- 已开启 STATE 的账号请求体最多检查 64 MiB；单次转发上限 10 分钟、等待响应头上限 60 秒。响应观察按单个事件 / JSON 上限 1 MiB 进行，超过该范围仍原样转发，但无法保证观察到模型异常。未开启账号的请求体采用流式转发，不施加该 64 MiB 检查上限。

## 开源、构建与验证

此插件根据官方公开插件协议独立实现，没有重新分发用户提供的官方插件二进制。感谢 [Sub2API](https://github.com/Wei-Shaw/sub2api)、[ccodex-sleep-state](https://github.com/gylive/ccodex-sleep-state) 及参与讨论测试的朋友。

```bash
cd plugin
go test -race ./...
node --test ui-tests/*.test.cjs
```

签名构建脚本在 [`scripts/package_plugin.py`](../scripts/package_plugin.py)。发布私钥保存在仓库外，**不在源码、插件或 Release 中**。自行构建者应生成自己的 Ed25519 密钥，并把 `plugin/release/` 的公钥和对应信任配置替换为自己的值；不要使用作者的 key ID 冒充原发布者。

```bash
python3 scripts/package_plugin.py build \
  --private-key /PRIVATE/PATH/publisher.pem --output ./artifacts
python3 scripts/package_plugin.py verify \
  --package ./artifacts/sub2api-state-kit_plugin_v0.3.4.s2plugin
```

测试覆盖范围与实际结果见 [插件验证记录](plugin-validation.md)。安装包不含作者的账号、代理凭据、API Key、数据库、STATE 或签名私钥。


### v0.3.3 界面补充

- 代理设置旁的「测试并应用代理」测试当前填写内容，成功后自动保存代理字段，失败保留原配置；不获取 STATE 或请求模型。支持前置代理串联，成功显示出口 IP 和国家。连通性操作最长等待 30 秒，页面为结果确认和自动保存保留 45 秒。
- 票据进度合并到参与账号的同一行，显示状态、剩余时间、尝试次数和错误；正在采集时禁用重复启动。
- 票据跨模型复用尚未在本轮实验中得到有效票据验证，当前仍保留按模型配置和验证的行为；不会把未验证的模型标为已恢复。

- 点击「查找票据」后先检查账号业务出口，再在每次动态采集前检查前置 / 动态代理；业务出口检查失败会停止；单个动态出口检查失败则按设定的尝试次数和间隔换出口，耗尽后在该账号行显示原因。IP 检测服务不可达也可能导致检查失败，不能据此断言所有目标均不可达。普通业务请求仍遵循无票据放行设置。
- 代理连通性结果使用醒目的红色失败、绿色成功、黄色检查中提示框。


### 单账号与批量查找、出口国家

- 单行「查找票据」直接启动该账号，不解除全局等待、不唤醒其他账号、不清理其他账号的冷却。
- 「全部已开启账号重新找票据」仅操作已保存、已开启且可用的账号；正在执行的任务不重复启动。
- 账号状态与日志显示「单账号手动」「全部手动」或「自动守护」；自动守护开启时，自动续期按各账号计划独立运行。
- 代理测试、账号行和每次探测日志按实际检测到的出口 IP 显示国家。国家由 api.country.is 查询，不根据代理服务器域名推断；仅发送公网 IP，不发送账号凭据或票据。查询有超时与缓存，失败显示「国家未知」，不影响采集和转发。开启「检测出口 IP 和国家并写入运行日志」可查看每次自动尝试的国家。


### 代理测试自动应用与手动模式

- 「测试并应用代理」通过后，仅自动保存被测试的动态代理地址和前置代理选择；不会夹带未保存的账号开关、套餐或高级参数。等待绿色「已自动保存并生效」后可直接查找，无需另点保存。失败或无法确认保存时明确提示，不显示为已生效。
- 测试期间锁定配置表单；只会处理这次测试对应的结果，旧结果不会触发保存。完成前关闭页面不会自动提交配置。
- 自动应用保存代理配置，并将本次测通的代理会话仅在进程内保留至测试开始后 1 分钟。网络配置和前置代理不变时，手动查找的首次尝试优先复用该会话；后续尝试换新会话，过期、网络失败、重新测试或修改网络配置后不再复用。复用会话不保证供应商固定公网 IP，仍以当次出口检测为准；本次未取得 IP 时显示「未取得 IP / 国家未知」。代理测试只检查 IP 检测站连通，不能证明账号授权或上游模型可用；401 会单独提示授权被拒绝。
- 新增「自动守护」开关。关闭并保存后，后台不再自动获取或续期，只执行单账号 / 批量手动操作，已有有效票据仍会注入。旧配置未包含此字段时继续保持自动守护，避免升级改变既有运行方式。如需完全手动操作，关闭此开关并保存。
- 每次尝试以轮次、账号和出口路径聚合展示，最终失败记录仍保留本次检测得到的 IP 和国家。没有出口信息时明确显示未知，不猜测国家。


### 国内部署：固定代理共用前置代理

在前置代理下勾选「账号业务代理也经过此前置代理（国内部署）」并保存。该选项默认关闭，旧配置保持原行为。按部署机器能否直达业务代理决定是否开启。

- 采集：本机 → 前置代理 → 动态池 → 上游。
- 业务请求、手动模型测试和票据复验：本机 → 同一个前置代理 → 账号固定代理 → 上游。最终出口仍是固定代理。
- 仅作用于插件账号列表内的 OpenAI OAuth 账号。关闭 STATE 总开关或单账号票据开关，仍保留此网络路径，便于做无票据对照；停用整个插件则由宿主接管。
- 未列入插件的账号、没有业务代理的账号和使用本机回环代理桥的账号保持原连接方式。回环地址不会交给远程前置代理解析，以免重复串联。
- 前置代理不可用时明确失败，不会绕过它直连。连接池区分前置代理和固定代理，凭据或前置路径变更不会错误复用连接；切换此选项会使旧路径票据重新获取验证。
- 「测试并应用代理」仍只测试及应用动态池的代理字段；此新增选项点击保存后生效。业务路径可在下方选择「账号业务出口」单独检测。

### 三步操作

配置页按「网络 → 账号 → 验证」排列。账号套餐和模型配置、高级参数、详细日志默认折叠。

- 账号开关点击即单独保存，保存失败会恢复原开关并在该行提示；新账号和套餐修改仍点击底部「保存设置」。
- 「查找票据」只操作当前行，立刻显示提交 / 获取进度；「测试此账号」只选中账号并滚动到验证区，不会自动发送请求。
- 模型测试和出口检测立即显示等待状态，运行中锁定输入并提供停止按钮。停止请求和超时分别提示，不把未完成请求当作模型路由结果。
- 结果明确显示所属账号、请求 / 返回模型、是否注入 STATE；切换账号时隐藏不属于当前账号的旧结果。收到 HTML / SVG 后才显示「查看 HTML」。
- 「快速检查 / 鹈鹕动画 / 糖果推理」只填入提示词，不自动测试。日志可按账号筛选。
- 代理测试仅在确认成功后自动应用代理地址。状态读取连续失败时超时解锁，未确认的代理不会保存；普通设置仍显式保存。
